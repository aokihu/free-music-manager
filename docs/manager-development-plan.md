# FreeMusic Manager 分阶段开发计划

## 1. 开发原则

- 后台作为独立项目和独立 Git 仓库维护。
- 每个阶段只建立一个可验收的闭环，不一次性开发完整后台。
- 桌面端与移动端同步实现；移动端保证管理能力，但不提供文件上传。
- 先用本地模拟数据确认后台信息结构，再连接文件导入和持久化。
- 现阶段只为前台提供已发布曲目的公开只读 API，不开放上传、编辑、状态或删除管理接口。
- 手动上传是当前内容生产方式，音频 Tag 是曲库元数据的主要来源。
- 每个阶段运行 `npm run lint`、`npm run typecheck` 和 `npm run build`。
- Git 提交和远程推送只在用户明确要求后执行。

## 2. 技术栈

- React / Next.js App Router
- TypeScript
- Shadcn UI
- Zustand
- Tailwind CSS v4

Zustand 仅在出现跨页面或跨组件的编辑状态后使用，不提前创建空 Store。

## 3. 阶段计划

### 阶段 0：独立工程基线

目标：建立可运行、可独立提交的后台项目。

任务：

- 在 `freemusic-manager` 独立目录初始化 Next.js 工程和 Git 仓库。
- 初始化 Shadcn UI，安装 Zustand。
- 增加后台项目说明、开发约束和分阶段计划。
- 保留最小的阶段提示首页，不实现业务功能。

不包含：

- 后台导航和曲库页面。
- 文件上传与 Tag 解析。
- 登录、R2、支付和前台 API。

验收：

- lint、类型检查和生产构建通过。
- 项目可独立启动，不依赖前台仓库。

当前状态：已完成。

### 阶段 1：响应式后台骨架

目标：建立后台的信息结构，不实现真实文件操作。

任务：

- 建立侧边导航、顶部操作区、概览和歌曲管理入口。
- 建立模拟歌曲列表，显示标题、Tag、发布状态和更新时间。
- 桌面端使用侧栏，移动端使用抽屉或紧凑导航。
- 只安装当前页面实际使用的 Shadcn 组件。

不包含：

- 文件上传、Tag 解析和数据保存。
- 登录与权限。

验收：

- 390px、768px 和 1440px 无横向滚动。
- 列表状态和主要操作可通过键盘识别和访问。

当前状态：已完成。桌面端提供固定侧栏和歌曲表格，移动端提供紧凑导航和歌曲卡片；概览数据与两种列表视图均来自同一份集中模拟数据。390px、768px 和 1440px 已通过真实浏览器检查，无横向滚动，导航、表格和状态标签具有明确语义。

### 阶段 2：歌曲文件夹导入与 Tag 预检

目标：让管理员选择音频并在保存前看到解析结果。

任务：

- 支持选择批量根目录或拖放多个歌曲文件夹。
- 每个歌曲文件夹严格包含一份 `__h` 高清音频、一份 `__l.ogg` 低清音频和一份 PNG/JPEG 封面。
- 以高清版解析标题、作者、风格、BPM 等标准 Tag；低清版仅记录试听文件技术信息。
- 将 mood、useCases、license、priceFen 等产品字段定义为明确的扩展 Tag 规范。
- 展示文件格式、时长、大小和缺失字段。
- 每个歌曲文件夹生成独立可编辑草稿，并按队列逐个保存。

不包含：

- R2 上传。

验收：

- 合法文件能够生成可编辑草稿。
- 不支持的格式和缺失必要 Tag 时给出明确提示。

当前状态：已完成并升级为批量文件夹模型。桌面端使用 Shadcn Dialog 选择批量根目录或递归读取拖放文件夹，根据相对路径将文件分组成歌曲单位。每个文件夹严格校验一份 `__h` 高清音频、一份真实 `__l.ogg` 低清音频和一份真实 PNG/JPEG 封面，不接受额外文件；高清版与低清版基础文件名必须一致。两个版本均展示格式、时长、大小、码率、采样率和声道，Tag 只从高清版提取；TITLE 无效时使用去掉版本后缀的基础文件名。批量草稿可以逐首展开编辑，保存时按歌曲顺序发起独立请求。移动端不渲染上传入口，只保留管理能力。

### 阶段 3：曲库清单与公开读取接口

目标：让前台通过稳定的只读接口读取已发布曲库和试听媒体。

任务：

- 编辑和确认导入后的歌曲字段，将高清版、OGG 低清版与外部封面保存到同一歌曲目录。
- 通过对象存储适配器和曲库仓库适配器隔离业务与持久化实现；开发模式固定使用本地文件和 JSON 曲库。
- 根据音频 SHA-256 生成稳定的歌曲 ID 和曲库清单 JSON。
- 输出已发布歌曲列表、封面和低清试听接口。
- 增加字段校验、重复 ID 和重复文件检查。

不包含：

- Cloudflare R2 和在线发布。
- 高清下载和下载权限验证。

验收：

- 单曲保存后刷新页面仍可从本地曲库读取；重复保存同一文件时更新同一记录。
- 已发布歌曲可被前台读取，草稿和已下架歌曲不可通过公开接口访问。
- 试听接口支持浏览器 Range 请求和稳定的缓存校验。
- 同一输入重复生成时不会产生无意义的数据变化。

当前状态：进行中。已完成双版本“保存到本地曲库”：Server Action 对每个歌曲文件夹重新校验命名、文件大小、OGG 文件头和 PNG/JPEG 文件头，并重新解析两份音频。每首歌曲保存到 `tracks/{trackId}/`，曲库使用 `audio.high`、`audio.low` 和必需的 `cover` 引用；不包含旧单音频兼容分支。本地对象存储适配器继续使用路径约束和原子写入，JSON 曲库仓库负责索引读取及串行写入，页面读取真实曲库。公开只读 API 已提供已发布歌曲列表、封面和低清 OGG 试听，支持 Range、HEAD、ETag 和 CORS；草稿及已下架歌曲统一返回 404。`NODE_ENV=development` 时适配器工厂固定组合本地文件与 JSON 曲库；`NODE_ENV=production` 时将根据 `DEPLOYMENT_PROVIDER` 选择 Cloudflare、AWS 或普通云服务器的整组适配器，当前尚未实现正式平台。高清下载权限仍属于后续小步。

### 阶段 4：歌曲编辑与发布状态

目标：补齐日常曲库维护能力。

任务：

- 增加草稿、已发布、已下架状态。
- 支持编辑 Tag、授权、价格和试听信息。
- 支持替换音频并保留稳定歌曲 ID。
- 增加删除和覆盖前的确认提示。

当前状态：进行中。已完成“歌曲信息编辑”、“发布状态管理”和“删除歌曲”三个小步：桌面歌曲表格和移动歌曲卡片均可编辑元数据、单独替换或删除 PNG/JPEG 封面，音频技术信息保持只读；没有封面时统一读取默认占位图。保存复用上传字段校验，并明确展示未保存、保存中、保存成功和保存失败状态。替换封面会在服务端重新检查扩展名、文件大小和真实文件头，更新曲库引用后清理旧封面。状态转换限制为草稿→已发布、已发布→已下架、已下架→草稿或已发布，每次操作均通过确认 Dialog，并在服务端写入队列内再次校验。删除操作通过独立确认 Dialog 执行，依次清理高清音频、低清 OGG、封面和曲库索引记录，本地适配器同时移除空歌曲目录并继续执行路径越界防护。删除服务已在临时曲库验证。音频替换仍属于后续小步。

### 阶段 5：批量导入与质量检查

目标：提高 AI BGM 批量入库效率。

任务：

- 支持批量选择和队列处理。
- 汇总缺失 Tag、重复内容和格式问题。
- 增加试听检查和批量发布前确认。

当前状态：进行中。已完成文件夹批量选择、递归拖放读取、结构汇总、双版本技术信息检查和顺序保存队列。上传草稿支持在高清版与低清 OGG 之间切换本地试听，所有歌曲共用一个播放器，并在关闭 Modal 或重新选择目录时停止播放和释放临时资源。批量发布前确认仍未实现。

### 阶段 6：管理员登录与持久化

目标：从本地工具演进为可部署的私有管理后台。

任务：

- 增加管理员身份验证和最小权限模型。
- 将草稿、歌曲和操作记录写入持久化存储。
- 增加必要的操作审计。

本阶段开始才引入服务端数据库或内部管理接口。

### 阶段 7：Cloudflare R2 发布

目标：由后台安全地上传和发布试听及完整文件。

任务：

- 分离试听文件和完整质量文件。
- 保存格式、码率、时长、大小和校验值。
- 支持替换、下架和发布失败重试。
- R2 凭据只保存在服务端。

### 阶段 8：授权、定价与权益边界

目标：为未来免费和付费下载准备管理能力。

任务：

- 管理免费、需要购买、已拥有和不可用状态所需字段。
- 使用整数分保存人民币价格。
- 管理授权文本版本、AI 生成来源和商业使用条款记录。

用户、订单、支付回调和下载权益属于后续独立阶段，不与曲库后台同时开发。

## 4. 固定执行顺序

每次开始新阶段时：

1. 复核目标、输入和不包含内容。
2. 实现最小可运行改动。
3. 检查桌面端和移动端主要路径。
4. 运行 lint、类型检查和生产构建。
5. 汇报结果，等待确认后再进入下一阶段。
